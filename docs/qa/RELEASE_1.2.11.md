# Проверка выпуска CamWork Translate 1.2.11

Выпуск объединяет исправления повторного запуска и оставшихся путей ошибок
выделения, AUTO и автозапуска. Клиентские жалобы относились к версии раньше
1.2.10; точный чекбокс восстановления не установлен. Ниже проверяются
конкретные механизмы актуального кода, без утверждения об общей причине
всех клиентских случаев.

## Выделение и окно перевода

- сохранённый master-switch не подменяется черновиком настроек;
- пауза записи клавиш снимается через finally, включая исключение;
- отмена draft-off после записи сочетания оставляет сохранённый ввод включённым;
- отказ Keymaster не отключает мышиное выделение; отказы регистрации повторяются;
- потерянная зарегистрированность GlobalScreen восстанавливается;
- исключение чтения clipboard не прекращает последующие попытки захвата;
- зависший UI Automation использует один worker и безопасный fallback, без очереди
  новых COM-задач и занятия общего пула перевода;
- внешняя отмена запроса распространяется, очередной запрос остаётся работоспособным.

В native lifecycle тестах применяется управляемый backend; они не меняют
глобальные hook или clipboard пользователя. Тихое удаление hook самой ОС при
сохранённом флаге библиотеки не объявляется воспроизведённым или обнаруживаемым.

## AUTO и языковая пара

- выбранный AUTO отделён от detected language во всех popup-представлениях;
- компактный список показывает AUTO, полная надпись начинается с режима;
- две разные детекции и обновление сервисов сохраняют выбранный режим;
- пассивный swap и смена языка не меняют основную пару;
- пассивное окно не наследует устаревшую детекцию основного;
- request, mapper, swap и доступность стрелок используют одинаковые source/target;
- проверяется сохранённая конфигурация через настоящий SettingsStore/DataStore
  и повторное чтение отдельной копии файла.

## Автозапуск Windows

- jpackage launcher имеет приоритет перед javaw.exe, путь корректно заключён в кавычки;
- существующий installer Run усыновляется только для текущей копии;
- сохранение ожидает операции Windows и проверки результата, ошибки возвращаются
  настоящему SettingsStore, не подтверждая ложный успех диалога;
- StartupApproved и политика читаются; системное решение не переписывается;
- отсутствующий Run не восстанавливается без явного включения;
- запись конфигурации ограничена по времени; ошибки диска вызывают rollback регистрации;
- проверяются таймаут записи, отмена и 40 конкурентных сохранений;
- при таймауте/восстановлении первоначального чтения startup reconciliation
  пропускается, чтобы не записать DEFAULT поверх настоящих настроек;
- smoke-проверки полностью отключают управление системным автозапуском;
- установщик удаляет только свою точную команду, чужая команда и её тип сохраняются;
- обновлённый Inno-код компилируется без установки приложения и изменения HKCU.

Реестр в unit-тестах заменён управляемой границей. Полная перезагрузка
клиентского компьютера не выполняется; подтверждается логика регистрации,
состояния отказа и фактический код упаковки.

## Повторный запуск

Исправляется воспроизведённый обход SingleInstanceGuard: в 1.2.10 защита
разрешила 17 из 24 параллельных повторных попыток, а занятый молчащим клиентом
listener разрешал второй запуск после таймаута.

Теперь блокировка ОС удерживается весь срок жизни приложения в стабильном
каталоге пользователя вне portable/installation/appData. Её файл не удаляется.
IPC передаёт только запрос показа окна: сбой или таймаут не предоставляет
право запуска. Файл endpoint хранится отдельно от блокируемого файла.

Проверяются следующие сценарии:

- 24 отдельных JVM с одновременным стартом и общим каталогом блокировки;
- штатное освобождение, повторное закрытие guard и запуск после него;
- принудительное завершение владельца и новый запуск при оставшемся lock-файле;
- повреждённые или недоступные метаданные IPC при удерживаемой блокировке;
- молчащий TCP-клиент и последующий корректный запрос показа окна;
- исключение обработчика показа окна без остановки listener;
- занятие прежнего порта сторонним приложением;
- узнаваемый handshake старой версии и совместимость нового listener;
- ошибки создания/открытия файла блокировки без запуска с обходом защиты.

Путь блокировки общий для всех установок одного пользователя. Отдельные
пользователи сохраняют независимые экземпляры. Два родственных Windows EXE
jpackage могут составлять одну цепочку запуска: это не показатель двух JVM.

Старая версия 1.2.10 не знает файловую блокировку. Перед portable-обновлением
её необходимо полностью закрыть, включая значок в трее. Установщик содержит
CloseApplications=yes. Исправление не меняет уже работающий старый процесс.

Выпуск также включает [исправления 1.2.10](RELEASE_1.2.10.md).
Публикация зависит от build/test на Windows, Linux и macOS и успешных
проверок готовых Windows/macOS-пакетов. SHA256SUMS.txt публикуется с файлами.

## Локальная проверка перед отправкой

Полный build smokeTestAllPlugins прошёл: 761 тест, 757 успешных,
4 пропущенных ручных теста производительности, 0 ошибок. Это на 70 тестов
больше набора 1.2.10. Отдельная проверка штатных плагинов: 44 успеха, 0 ошибок.

После сборки проведён дополнительный процессный прогон собранного fat JAR:
8 одновременных JVM, один владелец, 7 отказов повторного запуска; после
принудительного завершения владельца новая JVM успешно получила тот же lock.
Постоянный lock-файл сохранился. Рабочий переводчик пользователя не затронут.

verify-packaging.ps1 прошёл. Изменённый Pascal-код установщика принят
Inno Setup 6.7.3 с отключённым выводом файла; установка не выполнялась.
